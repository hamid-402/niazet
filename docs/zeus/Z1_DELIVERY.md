# تحویل Git و CI فاز Z1

تاریخ آماده‌سازی: ۲۰۲۶-۱۰-۲۶. این رسید، تکمیل تحویل فاز پذیرفته‌شده Z1 است؛ فاز جدید یا نسخه موازی پروژه نیست.

- گواهی اولیهٔ `z1-phase-acceptance.json` مربوط به پذیرش محلیِ پیش از commit و در تاریخچهٔ `5dd91a1` محفوظ است؛ acceptedCommit=null در آن، ادعای انتشار یا CI نبود. الحاق تحویل پایین فقط یک fixture تست را با آزمون تازه دوباره مقید کرده است؛ شواهد تاریخیِ HTTP/DB/UI به اجرای تازه تعبیر نمی‌شوند.
- مرجع یگانه همان Desktop/niazat-app و مخزن شخصی `hamid-402/niazet`، روی شاخه موجود `cursor/niazat-platform-build-8a4e` است. env، پکیج‌های نصب‌شده، storage، runtime و artifacts وارد Git نمی‌شوند. فایل staged نامرتبط وجود نداشت؛ فهرست تحویل به فایل‌های شناخته‌شده همین کار محدود و secret/license/SBOM دوباره بررسی شد.
- کنترل تصویری تحویل، سه اختلاف عمدیِ قبلاً اجراشده را آشکار کرد: برآورد هزینه در فرم، شارژ آزمایشی کیف پول و بسته‌بودن صحیح لینک‌های popover عملیات. هیچ عملیات یا لینکی حذف نشده؛ آزمون اختصاصی هشت‌حالته منو، بازشدن، صفحه‌کلید و ناوبری آن‌ها را جدا اثبات می‌کند.
- فقط ۲۴ حالت از سه سناریوی `customer-new-order`، `customer-wallet` و `ops-orders` پس از بازبینی تغییر کردند؛ ۱۶۸ حالت دیگر پیش از نوشتن baseline با مرجع قبلی مقایسه و برابر بودند. هیچ assertion، Axe یا سناریویی برای عبور تست خاموش نشد.
- اجرای کامل محلی موفق شد: ۱۹۲ screenshot و ۱۹۲ Axe اصلی، گردش‌های واقعی مجری، Ops/QC، پشتیبانی، Finance، مدیریت و تصمیم مشتری؛ ۲۰۰ تصویر/Axe تکمیلی این گردش‌ها؛ آپلود/دانلود واقعی، PDF/CSV، بازپرداخت/برداشت، Audit/ابطال نشست، حریم خصوصی و تسویه یک‌باره. داده و فایل آزمون صرفاً زیر DB تصادفی و artifacts بود و DB موقت حذف شد.
- flag کیف پول در fixture ایزولهٔ این آزمون صریحاً true و همه providerها mock هستند؛ وضعیت env توسعه‌دهنده یا نبود آن در Linux CI دیگر وضعیت fixture را تغییر نمی‌دهد. این تنظیم به production یا env اصلی مجوز شارژ آزمایشی نمی‌دهد.
- به CI موجود، آزمون‌های منفی pin/بازسازی تاریخی و پذیرش واقعی Z1 شامل wallet/auth، ۸۴ ردیف API و rehearsal ارتقای دارای سابقه افزوده شدند. wrapper فقط GitHub Actions و DB loopback با نام دقیق niazat_ci را می‌پذیرد؛ فایل env موجود را overwrite نمی‌کند، fixture موقت خود را در finally حذف می‌کند و هیچ --apply-local اجرا نمی‌کند. کنترل‌های قبلی CI، از جمله backup/restore و ماتریس تصویری، حفظ‌اند.
- پیشنهاد آپلود خودکار گزارش‌های جدید زئوس توسط auto-review به‌علت ارزیابی‌نشدن payload رد شد؛ آن پیشنهاد اعمال نشد. هیچ step آپلود تازه‌ای اضافه نشده است. گزارش‌های جدید محلی/موقت می‌مانند؛ ارسال جداگانه آن‌ها به مقصد خارجی بررسی و مجوز مستقل می‌خواهد.

## الحاق تحویل و مانع پذیرش آنلاین — ۲۰۲۶-۱۰-۲۶

- تحویل اصلی روی گیت شخصی با `5dd91a113a42f38c7dedda1192a06bafcbdb4ddb` push شد. CIهای push و PR همان SHA ناموفق شدند؛ [اجرای push](https://github.com/hamid-402/niazet/actions/runs/40285919042). بررسی وابستگی/مجوز/secret/SBOM موفق بود، نه کل CI.
- سه مرحلهٔ ناموفق: `API typecheck`، `Run runtime UI quality matrix` و `Zeus wallet, auth, API boundaries and populated upgrade rehearsal`. build وابسته اجرا نشد. علت دو مورد آخر بدون لاگ معلوم نیست و به تنظیمات Ubuntu یا DB نسبت داده نمی‌شود.
- annotation عمومیِ typecheck، دسترسی خصوصی `ConfigService.skipProcessEnv` را در fixture مالی نشان داد؛ محلی دقیقاً بازتولید شد. فقط همان fixture به mock متد عمومی `get()` با دادهٔ ایزوله تبدیل شد؛ همهٔ assertionها حفظ‌اند و کد محصول، داده، schema، نقش و مبلغ تغییر نکردند. typecheck API و اجرای تازهٔ ۴۵ مجموعه/۳۳۹ تست موفق و یک skip قبلی تأیید شد.
- pin همان یک فایل پس از بازبینی و اجرای تازه تمدید شد؛ `deliveryAmendment` گواهی، hash قبلی تست و فایل pin و commit تاریخی را نگه می‌دارد. جز این دو ورودی، ۸۶ ورودی دیگر، baseline ثابت و آزمون‌های رد drift حفظ‌اند. این اصلاح، موفقیت دو job دیگر یا پذیرش آنلاین را ثابت نمی‌کند.
- کنترل الحاق: lint و typecheck API، ۳۳۹ تست API و ۵۵ آزمون محافظ/مدارک تاریخی موفق؛ بازنویسی قالب همان fixture برای lint بدون تغییر منطق یا assertion انجام شد. پذیرش محلیِ گیت و محافظ ثابت دوباره بررسی شد.
- دریافت لاگ GitHub نیازمند ورود است و `gh` وارد حساب نیست؛ مسیر لاگ ۴۰۳ داد و تکرار/دور زده نشد. محدودیت نرخ درخواست عمومی نیز فعال شد؛ خواندن عمومی بیشتر متوقف و از مالک ورود با `gh auth login` یا دو لاگ مرتبط درخواست شد. اعتبارنامهٔ Git استخراج یا برای API بازاستفاده نشد.

**وضعیت تحویل نهایی:** پذیرش محلی شش بند Z1 برقرار است، اما پذیرش آنلاین و بستن تحویل تا رفع دو شکست با شاهد واقعی و CI موفق همان نسخه باز است. هنوز وارد Z2 نمی‌شویم. لاگ محدودشده بدون احراز هویت خوانده نمی‌شود؛ مشاهده عمومیِ وضعیت job جای دسترسی به لاگ حفاظت‌شده را نمی‌گیرد.

پس از تأیید تحویل، نقطه بعد همان Z2 «قیمت، مهلت و ظرفیت» است؛ Z1 شش بندِ محلی پذیرفته دارد و Z0/Z1 دو فاز از ده فازِ پذیرش محلی‌اند، نه دو تحویل آنلاین موفق. این وضعیت، انتشار عمومی، فعال‌سازی Provider/AI زنده، یا بستن هسته/M5/P4 نیست.
